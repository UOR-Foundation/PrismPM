# Browser-system source fixture

`Release.lex.tex` models A/B releases for the language-1.2 `Calculator.lex.tex`
beside it, selected through this fixture's LexLean configuration (which also
declares the `prism.arch` lexicon the stdlib modules title themselves from).
Both models and manifests bind
`sha256:fd6aadc5719e3a5a2ac864f51c92809dc836c058eee38b2729d0b49def8996f9`.

The accepted LexLean reconstruction revision changed the projected application
identity, but this committed fixture still named its prior model. Source V&V
missed the drift because `browser_system_project` silently rebound the copied
fixture before checking it. That helper now preserves the committed bindings,
matching the installed product gate. Deliberately constructed test models still
use the explicit binding helper; ordinary verification never repairs source.

The four bindings were regenerated by the existing `bind_application_digest`
owner: the real LexLean `Engine` snapshot, PrismPM `project_application`, canonical
model encoding and `lexlean::sdk::write_module`. They were not copied from a
diagnostic. [The isolated writer run](https://github.com/UOR-Foundation/PrismPM/actions/runs/43205960558)
at `0d181eb349d863f8e325a9fa3f6f2de6a3bf7e0e` retained the original PP2101 refusal,
canonical model bytes, generated notation, installed public `check` result and
passing source-selection/requirements and missing-command-line regressions.
Artifact `browser-binding-proposal` (13939057663) has ZIP SHA-256
`aee7d50e3fddbce33d813ef7594a427ff2e35dc3ce22f650f101d010135b6d53`.
The actual installed CLI independently returned the same model identity.
Its immutable diagnostic SDK was
`ghcr.io/uor-foundation/prismpm-sdk@sha256:454d1746503d62be3b9837268c4183b216ea8872e79e47d0ab694e0704a54b79`;
this writer run does not qualify or release that SDK.

Run in a Docker-enabled devcontainer with the immutable imported-oracle image
available to its daemon (no image pull is performed by the oracle runner):

```sh
export PRISMPM_TEST_SDK_IMAGE=ghcr.io/uor-foundation/prismpm-sdk-candidate@sha256:60226bc791d4c0e5613402a6be7e63f4963d3faf7f327befcf56fc0e41d0ce21
cargo test --locked --offline -p prismpm --lib browser_system_ -- --nocapture --test-threads=1
cargo xtask conformance system-oci
```

All three original owners must pass, including named A/B proofs, real SPDX
oracles and source-free export. These source checks do not qualify the installed
SDK, Foundry deployment or release. The image supplies imported oracle tooling
only; it is not accepted as the current SDK. Historical evidence remains in Git
history.
